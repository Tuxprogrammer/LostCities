# Block tags

The six Lost Cities block tags: what the shipped files contain, how the data generator builds them, and what each one changes during generation. Lost Cities registers no blocks or items of its own at the pin; its only registry entries are the features `lostcities:lostcity` and `lostcities:spheres`.

| # | Field | Contents |
|---|---|---|
| 1 | **Identity** | `worldgen/LostTags` (six `TagKey<Block>` constants), `datagen/LCBlockTags` (Forge `BlockTagsProvider`, registered by `datagen/DataGenerators` on `GatherDataEvent`), shipped files `src/generated/resources/data/lostcities/tags/blocks/{easybreakable,foliage,lights,needspoi,notbreakable,rotatable}.json` (added to the jar as a resource directory). Helpers `varia/Tools.hasTag` and `getBlocksForTag` (out of scope). |
| 2 | **Inputs** | The tag files, as loaded and possibly overridden by data packs; the block being placed or damaged. |
| 3 | **Numbers** | Easy-breakable damage multiplier 2.5. Damage threshold for the iron-bars variant `BLOCK_DAMAGE_CHANCE` 0.7 (03-terrain). Counts: `easybreakable` 39 blocks, `foliage` 6 tags, `lights` 44 blocks, `needspoi` 12 blocks, `notbreakable` 4 blocks, `rotatable` 2 tags. |
| 4 | **Behavior** | See [Consumers](#consumers). |
| 5 | **Determinism** | None of their own. The state sets built from `lights` and `needspoi` are built once per terrain feature under a lock and are immutable. |
| 6 | **Data formats** | 1.20 tag JSON: `{ "values": [ "<block id>" or "#<tag id>" ] }`, no `replace` field (defaults to false, so data packs can add entries). |
| 7 | **Output** | Membership tests; no world output of their own. |
| 8 | **Relationships** | `LostCityTerrainFeature` (03-terrain: part writing, terrain correction, rotation), `DamageArea` (03-terrain: explosion damage). |
| 9 | **1.20 dependencies** | Block tags and data-pack tag loading; Forge tag `#forge:glass`; vanilla tags `#minecraft:leaves`, `#minecraft:flowers`, `#minecraft:bamboo_blocks`, `#minecraft:logs`, `#minecraft:coral_plants`, `#minecraft:saplings`, `#minecraft:stairs`, `#minecraft:doors`; data generation; per-state light emission; the POI system; `BlockState.rotate`; many 1.13+ blocks in the lists. |
| 10 | **Bugs** | `LOOT-07`, `LOOT-08`, `LOOT-09` |

## Shipped contents

### `lostcities:easybreakable`

`minecraft:glass`, `minecraft:glowstone`, the 16 `minecraft:<color>_stained_glass` (white, orange, magenta, light_blue, yellow, lime, pink, gray, light_gray, cyan, purple, blue, brown, green, red, black), `minecraft:glass_pane`, `minecraft:beacon`, the 16 `minecraft:<color>_stained_glass_pane` (same colors), `minecraft:sea_lantern`, `minecraft:conduit`, `minecraft:tinted_glass`. 39 entries.

The data generator at the pin would instead write only `#forge:glass` (`LCBlockTags.java:246`). The shipped list matches an older generator that collected blocks by glass material, which is why glowstone, beacon, sea lantern and conduit are present (`LOOT-07`). The shipped file is what the mod uses.

### `lostcities:foliage`

`#minecraft:leaves`, `#minecraft:flowers`, `#minecraft:bamboo_blocks`, `#minecraft:logs`, `#minecraft:coral_plants`, `#minecraft:saplings`. Matches the generator.

### `lostcities:lights`

`minecraft:lava`, `brown_mushroom`, `torch`, `wall_torch`, `fire`, `soul_fire`, `redstone_torch`, `redstone_wall_torch`, `soul_torch`, `soul_wall_torch`, `glowstone`, `nether_portal`, `jack_o_lantern`, `enchanting_table`, `brewing_stand`, `lava_cauldron`, `end_portal`, `end_portal_frame`, `dragon_egg`, `ender_chest`, `beacon`, `light`, `sea_lantern`, `end_rod`, `end_gateway`, `magma_block`, `sea_pickle`, `conduit`, `lantern`, `soul_lantern`, `campfire`, `soul_campfire`, `shroomlight`, `crying_obsidian`, `amethyst_cluster`, `large_amethyst_bud`, `medium_amethyst_bud`, `small_amethyst_bud`, `sculk_sensor`, `calibrated_sculk_sensor`, `sculk_catalyst`, `ochre_froglight`, `verdant_froglight`, `pearlescent_froglight` (all `minecraft:`). 44 entries.

Generated by listing every registered block whose **default** state emits light, at data-generation time in a vanilla-only environment. Blocks that emit light only in some states (lit furnace, lit redstone lamp, candles, glow lichen) and blocks from other mods are absent (`LOOT-08`).

### `lostcities:needspoi`

`minecraft:brewing_stand`, `cauldron`, `barrel`, `blast_furnace`, `smoker`, `composter`, `fletching_table`, `lectern`, `stonecutter`, `loom`, `smithing_table`, `grindstone`. Matches the generator.

### `lostcities:notbreakable`

`minecraft:bedrock`, `end_portal`, `end_portal_frame`, `end_gateway`. Matches the generator.

### `lostcities:rotatable`

`#minecraft:stairs`, `#minecraft:doors`. Matches the generator.

## Consumers

| Tag | Where | Effect |
|---|---|---|
| `foliage` | `LostCityTerrainFeature.isFoliageOrEmpty` | (server) Terrain correction treats empty blocks, `#minecraft:climbable` blocks and foliage as see-through when looking for the real surface, so trees and plants are not moved as ground (03-terrain). |
| `rotatable` | `LostCityTerrainFeature.transformBlockState` | (server) When a part is placed with a rotation, a block in this tag is rotated with `BlockState.rotate`. Rails and powered rails get their shape transformed separately. Every other block keeps the state written in the palette (`LOOT-09`). |
| `easybreakable` | `DamageArea.damageBlock` | (server) Explosion damage for these blocks is multiplied by 2.5 before the destroy roll, as if they took 2.5 times the damage. |
| `notbreakable` | `DamageArea.damageBlock` | (server) These blocks are never changed by explosion damage. |
| `lights` | `LostCityTerrainFeature` part writing | (server) Every state of every block in the tag is collected once. When a part places one of these states (and the palette entry has no torch, loot, mob or block-entity info), the position is queued for a light update with the client-update flag. |
| `needspoi` | `LostCityTerrainFeature` part writing | (server) Every state is collected once. When a part places one of these states, `minecraft:dirt` is written instead and a post-todo is queued; in `ChunkFixer.fix` the todo sets the real block (no update flags) if the position still holds dirt. Setting it through the world, rather than into the chunk buffer, is what lets the game register the block's point of interest (*inferred* from the code comment and 1.20 behavior). |

Precedence when writing a part block: palette torch, then loot, then mob, then block-entity tag, then `needspoi`, then `lights`, then the sapling and small-flower handling. A block in both `needspoi` and `lights` (`brewing_stand`) is handled as `needspoi` only.

## Data generation

`LCBlockTags.addTags` (data generation only, never at runtime):

1. Add the six vanilla plant tags to `foliage`.
2. Add `#forge:glass` to `easybreakable`.
3. Add every registered block whose default state's light emission is above 0 to `lights`.
4. Add `#minecraft:stairs` and `#minecraft:doors` to `rotatable`.
5. Add bedrock, end portal, end portal frame and end gateway to `notbreakable`.
6. Add the 12 workstation blocks to `needspoi`.

Provider name: `LostCity Tags`.
