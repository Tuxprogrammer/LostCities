# 05 · Assets

How Lost Cities: New Horizons carries over upstream's JSON asset system: the thirteen asset types, how they are loaded, overridden, validated and compiled, how a part's characters become 1.7.10 blocks, and the 322 bundled asset files. Upstream's behavior is in [original-spec/05-assets](../../original-spec/05-assets/index.md). The decorative block catalog and its variety pools are their own sub-area, [block-catalog/](block-catalog/index.md); this index links them and does not repeat them.

Status: *Accepted* where a row cites a decision record or a decision-log row; *Proposed* where it says so, with the recommendation in [Proposed, not decided](#proposed-not-decided). Bug IDs are from [BUGS.md](../../original-spec/BUGS.md); a row that names one fixes it, and the port carries a regression test for it ([0001](../../design/0001-port-policy-and-licensing.md) §2). Facts about other mods are *verified* with a pinned permalink or marked *unverified* ([new-spec README](../README.md#how-to-read)).

## Summary

- **Same asset system, plain Java.** Upstream's one-file-per-asset JSON layout, field names and defaults are kept ([D14](../../design/decision-log.md)). Codecs and data-pack registries become hand-written parsing into an immutable model in `lostcities.asset`, with no Minecraft type in it ([CONTRIBUTING § Architecture](../../../CONTRIBUTING.md#architecture), D6).
- **Loaded once, at `postInit`,** from the jar and then from `config/lostcitiesnh/assets/`, which overrides it (D14). Everything is resolved and validated at load, so a bad asset fails there, with its file and field, never mid-generation ([CONTRIBUTING § Code standards](../../../CONTRIBUTING.md#code-standards)).
- **Upstream's JSON is reused under MIT; its textures are not** ([0001](../../design/0001-port-policy-and-licensing.md) §5). Converted assets keep upstream's 1.20 block names; one mapping table turns them into `modid:name` plus metadata at load (D14, [D19 block mapping](../00-pack-integration/block-mapping.md)).
- **Variety on top of the mapping.** Palettes draw weighted variety from the pack's decorative blocks per role, under the rules of D25, D28 and D29, with decorative-metal flags and the cabin exception ([block catalog](block-catalog/index.md)).
- **Palettes may carry tile-entity data** (D28 rule 6), generalizing upstream's chest, spawner and furnace entries.
- **All 33 upstream asset bugs are fixed or made impossible**, most of them by validating at load what upstream let crash later.

The 1.7.10 asset format (folders, names, block references, matchers, tile-entity templates and the load-time checks) is detailed in [asset-format.md](asset-format.md).

## Proposed, not decided

Each item names the recommendation. None blocks M02's start: the defaults below are what M02 builds unless the owner redirects.

### P05-1 Folder layout

Where converted assets sit in the jar and in the override folder. **Recommendation:** keep upstream's tree verbatim as a jar resource, `data/<namespace>/lostcities/<type>/<path>.json`, so a re-pin diffs file for file (D14's reason), and mirror it under the override folder as `config/lostcitiesnh/assets/<namespace>/<type>/<path>.json`. The id stays `<namespace>:<path>`.

### P05-2 One name form

Upstream compares short names in conditions and full ids in matchers (ASSET-33). **Recommendation:** normalize every asset name to a full id at load (a bare name means `lostcities:<name>`) and compare full ids everywhere: condition tests, name matchers, selectors and references. Bundled assets keep their bare names and behave as upstream intends; an override in its own namespace writes `ns:name` once and it matches everywhere.

### P05-3 Asset-set hash warning

The pinned snapshot records the asset-set hash ([0005](../../design/0005-rwg-overlay.md#7-profile-selection-q7) §7), but nothing says what happens when it differs at a later start. **Recommendation:** log one warning naming the changed asset files, as [0006](../../design/0006-build-around-other-worldgen.md) §2 does for changed oracle config, and carry on: an owner who edits assets on a live world chooses the seam at the border of new chunks.

### P05-4 Native block references

Converted assets keep 1.20 names (D14), but variety pools and owner overrides name pack blocks directly, and the [catalog](block-catalog/index.md#prerequisites-for-the-asset-system) needs names with spaces, pipes, dots and metadata above 15. **Recommendation:** upstream 1.12's form, `modid:name@meta` (meta optional, default 0), for a direct 1.7.10 reference: `@` cannot appear in a 1.20 id, so the two forms never collide, and 1.12 is the reference branch [0001](../../design/0001-port-policy-and-licensing.md) §6 names. A string without `@` and with one colon is a 1.20 name and goes through the mapping table. In block matchers, an ore-dictionary name is written `ore:<name>` (`#forge:stone` converts to `ore:stone`). Details in [asset-format.md § Block references](asset-format.md#block-references).

### P05-5 Desert rubble

ASSET-20: the desert brick palettes and `default_desert` lack `}`, so ruined desert buildings leave no rubble, and the catalog has no desert rubble pool. **Recommendation:** a `sandstone_rubble` variant in the shape of upstream's `stonebrick_rubble` (about 70 % full blocks, the rest slabs and stairs): `minecraft:sandstone:0` and `:2`, `minecraft:stone_slab:1`, `minecraft:sandstone_stairs`; `bricks_desert_red` and `_orange` take the same set, with Et Futurum's red sandstone and its slabs for the red palette. `default_desert`'s missing `;` needs nothing: no part uses `;`.

### P05-6 Biome vocabulary

Upstream's biome matchers use 1.20 biome ids and tags (`#minecraft:is_ocean`, `is_river`, `is_beach`, `is_deep_ocean`; `minecraft:desert`, `minecraft:badlands`). 1.7.10 has numeric biomes with names and Forge's `BiomeDictionary` types. RWG2 and classic RWG report their own base biomes and register each with dictionary types: oceans as `OCEAN` and `BEACH`, rivers as `RIVER`, the hot desert as `HOT`, `DRY`, `SANDY`, and no biome with the `MESA` type or a "deep ocean" name (*verified:* RWG2 [BaseBiomes.java#L22-L27](https://github.com/GTNewHorizons/Realistic-World-Gen-2/blob/2.0.6/src/main/java/rwg2/biomes/base/BaseBiomes.java#L22-L27), [#L64-L103](https://github.com/GTNewHorizons/Realistic-World-Gen-2/blob/2.0.6/src/main/java/rwg2/biomes/base/BaseBiomes.java#L64-L103); classic RWG [BaseBiomes.java#L19-L24](https://github.com/GTNewHorizons/Realistic-World-Gen/blob/alpha-1.5.3/src/main/java/rwg/biomes/base/BaseBiomes.java#L19-L24), [#L41-L63](https://github.com/GTNewHorizons/Realistic-World-Gen/blob/alpha-1.5.3/src/main/java/rwg/biomes/base/BaseBiomes.java#L41-L63); the provider reports base biomes, [other-worldgen.md](../00-pack-integration/other-worldgen.md)). **Recommendation:** matcher entries are either a dictionary type, written `type:OCEAN`, or a 1.7.10 biome name, written `name:Hot Desert`, matched case-insensitively. The converted bundled assets use types: `is_ocean`, `is_river` and `is_beach` become `type:OCEAN`, `type:RIVER` and `type:BEACH`; the desert city style's `minecraft:desert` and `minecraft:badlands` become `type:SANDY` with `excluding type:OCEAN`; `is_deep_ocean` has no type and is handled in [07](../07-scattered/index.md#p07-2-deep-ocean-for-the-oil-rig). Which city style a biome gets is `02-profiles-dimensions`' to confirm.

### P05-7 Moss block

`minecraft:moss_block` fills 68 of 128 slots of upstream's rubble-dirt default (Java code, `03-terrain`), and the pack's Et Futurum config leaves it off (`enableMossAzalea=false`, [etfuturum.md](block-catalog/etfuturum.md)). **Recommendation:** `minecraft:mossy_cobblestone`, which the default already uses for 40 slots, so the default becomes stone bricks (mossy) 20 and mossy cobblestone 108; the catalog's [overgrowth](block-catalog/index.md#overgrowth) pool adds variety on top. To be added to the D19 table.
