# 06 · Highways and railways

The highways that link cities and the railways, stations and rail dungeons that run under and between them, over RWG terrain. Upstream's default intercity highway planner and its railway grid ([06-highways-railways](../../original-spec/06-highways-railways/index.md)) carry over; the legacy noise highways, the planner's thread pool and its saved hub data do not (D11), and monorails wait with the sphere landscapes (D12). Heights come from the RWG height oracle and biomes from RWG's biome provider ([0005](../../design/0005-rwg-overlay.md)); landmark cores are obstacles the planners route around or end before ([0006](../../design/0006-build-around-other-worldgen.md#consequences), M06); highways and primary roads are where speed blocks are walked on (D28 rule 3).

Status: *Accepted* where a row links a design record or decision-log row. Rows and items marked *Proposed* are this spec's suggestions, collected with a recommendation in [Proposed, not decided](#proposed-not-decided). Parts are written by the terrain phase ([03-terrain](../03-terrain/pipeline-on-rwg.md#stage-map)); the planners are pure Java in `layout` (D6).

## Proposed, not decided

1. **Highways around landmark cores.** 0006 makes cores obstacles; the roadmap's M06 says the planners "route around them or end before them". *Recommendation*, in this order, all pure and computed by the route's owner cell when the route is built:
   1. Shape choice: among the railway-clear shapes, prefer one whose segments cross no core; then upstream's city penalty; then upstream's shape hash. Candidates and selections stay upstream's, so the network's topology does not change.
   2. Detour: where every clear shape crosses a core, the route leaves its line one chunk before the core's bounding box, runs parallel one chunk past it on the shorter side (ties: north, then west, as for severed primary roads in 0006 §3), and rejoins one chunk after it, with upstream's bend parts at the four corners and the route's own level throughout. A detour segment that would lie along a railway row or column moves one chunk further out.
   3. Dead end: where a detour would meet another core, or would need more than 8 chunks of sideways offset, the highway ends one chunk before the core on each side with a straight piece, as upstream's highways end at hubs.
   Oracle lookups along a route go through the bounded per-cell oracle caches, so the cost is a few lookups per route.
2. **Hub samples in a core.** *Recommendation:* skip them, as samples below the minimum score are skipped, so a hub (and with it a route's end) never lies in a core.
3. **HWY-09: one level where routes overlap.** *Recommendation:* every route that shares a chunk on the same axis with another route takes the lowest original level among the routes it shares chunks with, along its whole length. One step, not repeated, so the rule stays bounded by the 25-cell query; a chain of three or more routes at different levels can still leave a jump, which the debug command lists and the M06 screenshots check.
4. **Railways and landmark cores.** Under the accepted rule (0006 §1, no railway in a core) the fixed grid cannot detour. *Recommendation for the rule as it stands:* a rail chunk in a core is `NONE`; the rail chunk before it on its line becomes `RAILS_END_HERE` facing the core (vertical lines use `rails_horizontal_end` rotated 90°, since upstream has no vertical end part); a station whose spot is in a core is dropped, and a station whose spot is an edge-ring chunk is underground. *Recommendation to the owner, as an amendment to 0006 §1:* let a railway at the railway level (not stations, extensions, descents or staircases) pass under a core when its part's top is at least 8 blocks below the lowest oracle ground of that core chunk. The grid's lines run every 10 chunks and a village footprint reaches up to 112 blocks from its start, so under the strict rule most villages near a line would cut it; underground, nothing shows at the surface, though a cave in the core can expose the tunnel, as rails are exposed everywhere outside cities upstream.
5. **A per-world switch for highways** (HWY-06). *Recommendation:* a profile option `highwaysEnabled`, default true, pinned with the rest of the profile, beside upstream's `railwaysEnabled`; the module flag stays the server-wide switch.
6. **`highwayNetworkLevel`'s range.** *Recommendation:* clamp it at load to the highest level whose tallest bundled highway part (12 blocks, `highway_open`) ends at or below Y 255: 28 at `groundLevel` 71, computed from the profile's own ground level, with a warning. This applies 0005 §6's clamp rule to an option counted in levels.
7. **The railway's lowest Y.** *Recommendation:* reject at load a profile whose `groundLevel` and `railwayLevelOffset` put the railway's part Y below 5, so rails never cut into RWG's bedrock band.
8. **Planning cost.** *Recommendation:* keep the planner synchronous (D11), and add a server-tick task that computes hub cells ahead of each player within the search radius under a fixed time slice per tick, so a chunk seldom pays for a fresh area. The task changes nothing generated, only when pure values are computed. M06 measures whether B4 holds on the first chunks of a fresh region; if not, the budget for those chunks is a question for 0005.
