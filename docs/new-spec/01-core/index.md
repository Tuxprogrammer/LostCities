# 01 · Core

How Lost Cities: New Horizons boots, what it registers, how it is configured, which commands it has, its network channel, its public API, its in-game part editor, its spawn handling and the shared utilities and random generators, set against upstream's [01-core](../../original-spec/01-core/index.md). Upstream's behavior is there; this area records only what changes and why.

Status: the rows that cite a design record or a decision-log row are *Accepted*. Rows or details marked *Proposed* are this spec's suggestion; each one is listed with a recommendation in [Proposed, not decided](#proposed-not-decided). Facts about Forge and other mods are *verified* with a pinned permalink or a pack config path, as the [new-spec README](../README.md#how-to-read) requires.

## Contents

- [commands.md](commands.md): the `/lostcities` command set on 1.7.10, every subcommand with its fate, permission, arguments, output and file writes

## How to read the deviation table

- **Original** links the upstream sheet or section. One row per sheet, and one per significant system or tunable in it.
- **Here** is one of *same*, *changed*, *dropped*, *deferred* or *new*. *Same* still means a port under the [ported-code gate](../../../CONTRIBUTING.md#ported-code): our style, Java 8 API, Javadoc, tests.
- **What changes** names the 1.7.10 and Forge 10.13.4.1614 counterpart where the API differs ([API-MAP](../../original-spec/API-MAP.md)).
- **Decision** links the design record or names the [decision-log](../../design/decision-log.md) row. "Bug register" means the change follows from [CONTRIBUTING § Workflow](../../../CONTRIBUTING.md#workflow) item 3 (upstream bugs are never reproduced) and nothing more specific.
- **Avoids** lists the [BUGS.md](../../original-spec/BUGS.md) IDs the change must not reproduce. Each needs a `doesNotReproduce<ID>_…` regression test where the code path exists in the port.

### Mod config

Upstream: [config.md](../../original-spec/01-core/config.md). Upstream has three `ForgeConfigSpec` TOML files, one of them per world. Here there is **one GTNHLib annotation config**, `config/lostcitiesnh.cfg`, plus the folders `config/lostcitiesnh/profiles/` and `config/lostcitiesnh/assets/`. GTNHLib names the file after the mod ID ([Config.java#L14-L35](https://github.com/GTNewHorizons/GTNHLib/blob/0.11.54/src/main/java/com/gtnewhorizon/gtnhlib/config/Config.java#L14-L35); [ConfigurationManager.java#L61-L99](https://github.com/GTNewHorizons/GTNHLib/blob/0.11.54/src/main/java/com/gtnewhorizon/gtnhlib/config/ConfigurationManager.java#L61-L99), registered "before or during preInit"). 1.7.10 has no per-world config ([0005](../../design/0005-rwg-overlay.md) Alternatives), so **every key that changes what a world generates is copied into the world's pinned profile when the world is created**, and later edits affect new worlds only ([02 · pinned profile](../02-profiles-dimensions/pinned-profile.md)). Keys that change no generated block are read live.
